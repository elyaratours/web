## Why

Most tourism visitors will likely discover and evaluate the site from a phone, so the mobile experience needs to feel intentional rather than like the desktop layout stacked vertically. Current responsive behavior works, but mobile navigation, spacing, media sizing, cards, and calls to action can be made clearer and more polished.

## What Changes

- Improve mobile navigation so visitors can reach tours, tailor-made trips, blog, contact, and language switching without relying on the footer.
- Refine mobile typography, spacing, image heights, card padding, and button behavior across localized public pages.
- Make key reservation and contact calls to action easier to find and tap on small screens.
- Polish the home page sections, tour cards, blog cards, traveler reviews mosaic, tour detail pages, blog detail pages, contact pages, and tailor-made pages for mobile viewports.
- Preserve the established Granada tourism visual language, content model, external email reservation flow, and desktop layout intent.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `static-tourism-site`: Add explicit mobile experience requirements for navigation, readability, media sizing, tappable actions, and key public page layouts.

## Impact

- Affected code: global layout, global styles, home page sections, card components, traveler reviews mosaic, tour/blog detail pages, contact page, and tailor-made pages.
- Affected public behavior: mobile visitors get clearer navigation, more comfortable content density, more usable calls to action, and less vertical friction.
- No new dependencies, backend services, booking/payment systems, content collection changes, or image asset requirements are expected.
