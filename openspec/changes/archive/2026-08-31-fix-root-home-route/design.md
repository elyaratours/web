## Context

The app is a static Astro site deployed at custom-domain root routing on GitHub Pages. It currently has a standalone root page at `src/pages/index.astro` plus localized home pages generated by `src/pages/[locale]/index.astro` for `/es/` and `/en/`.

## Goals / Non-Goals

**Goals:**

- Make `/` resolve to the approved Spanish home page at `/es/` without keeping a second marketing home in sync.
- Keep the existing localized home implementation as the source of truth for home content.
- Preserve GitHub Pages static hosting compatibility.
- Avoid showing the root-only hero copy that the site owner rejected.

**Non-Goals:**

- Do not redesign the Spanish or English home pages.
- Do not add language detection, cookies, local storage, or per-user redirect behavior.
- Do not change tour content, reservation links, blog routes, or navigation structure beyond root URL behavior.

## Decisions

- Use `/es/` as the canonical default destination for `/`.
  - Rationale: the business content and primary site language are Spanish, and `/es/` already contains the approved localized home content.
  - Alternative considered: duplicate the Spanish home at `/`. This would avoid a redirect but would create two home sources to keep consistent and increase SEO duplicate-content risk.

- Replace the root page content with a static-host-compatible redirect or equivalent minimal root response.
  - Rationale: GitHub Pages cannot rely on server-side redirects, so the implementation must produce behavior that works from static files.
  - Alternative considered: keep the current root page and only edit the copy. This leaves an unnecessary third home experience and does not prevent future drift from `/es/`.

- Do not implement browser language auto-routing.
  - Rationale: deterministic routing is simpler, testable, and avoids surprising users or crawlers. Visitors can still switch language through existing `/en/` navigation.

## Risks / Trade-offs

- Static redirect behavior differs from HTTP 301/302 server redirects -> verify the built `dist/index.html` works on static hosting semantics and includes a clear fallback link.
- `/` becomes Spanish-first -> keep existing language switch links so English visitors can reach `/en/` from localized navigation.
- Search engines may briefly retain old root content -> ensure root metadata/canonical behavior points to `/es/` or the generated root page does not expose the rejected copy.

## Migration Plan

1. Update `src/pages/index.astro` so `/` no longer renders standalone marketing content and instead resolves to `/es/` with static-host-compatible behavior.
2. Build the site and inspect or smoke-test the generated root output.
3. Rollback by restoring the previous `src/pages/index.astro` content if the static redirect does not work as expected.
